AgentOS Blueprint

OmniCompute: KubeEdge Collaborative AI Architecture

A CNCF-aligned initiative to accelerate the adoption of generative and agentic AI across the device-edge-cloud continuum.

By: Shane Wang

Executive Summary

Unified AgentOS Reference Architecture

This proposal establishes the KubeEdge Collaborative AI Blueprint as a CNCF-aligned initiative to accelerate the adoption of generative and agentic AI across the device-edge-cloud continuum.

Reference Architecture

Define OmniCompute for AgentOS spanning devices, edge nodes, and the cloud.

Reusable Implementations

Deliver tested implementations of intelligent routing, privacy guardrails, and local inference gateways.

Seamless Orchestration

Leverage KubeEdge to ensure seamless AI workload orchestration, unified API access, and dynamic task scheduling.

Background

The Edge-Cloud AI Challenge

As AI use cases evolve toward multi-modal and agentic systems, relying solely on centralized cloud data centers presents insurmountable challenges regarding bandwidth costs, unpredictable network latency, and strict data privacy regulations. Conversely, edge devices alone lack the hardware resources to run massive parameter models.

KubeEdge, as a leading cloud-native edge computing framework under CNCF, natively extends Kubernetes orchestration to the edge. By leveraging KubeEdge's robust edge-cloud synchronization and combining it with lightweight inference gateways, we can build a collaborative closed-loop system: edge devices handle sensitive and low-latency tasks locally, while complex reasoning is seamlessly routed to the cloud.

Problem Statement

Severe Fragmentation at the Edge

Enterprises deploying Agents (especially LLMs) at the edge face severe fragmentation across multiple dimensions.

Compute

Compute/Model Mismatch

Edge devices (Local XPUs) cannot independently host ultra-large models and lack the capability to dynamically decompose or route complex tasks to the cloud.

Privacy

Privacy & Compliance Risks

Transmitting raw edge data directly to the cloud expands the attack surface and risks PII leakage. There is a lack of unified data desensitization and policy enforcement.

Routing

Rigid Routing

Current systems lack intelligent inference routing based on token cost, network latency, and task complexity.

Management

Siloed Environments

Managing heterogeneous deployments, model distribution, and microservices across the edge-cloud continuum lacks a unified control plane.

Goals & Scope

Blueprint Objectives

Unified Inference Interface

Provide a standardized microservice/API layer for AI Agents, masking the underlying edge-cloud topology.

Intelligent Compute Dispatching

Dynamically allocate inference requests between local edge XPUs and cloud accelerators (e.g., Gaudi, standard GPUs) based on task complexity and resource availability.

Enterprise-Grade Privacy

Enforce strict data isolation, redaction, and policy checks at the edge before any cloud transmission.

Reusable Reference Implementations

Deliver a blueprint that can be adopted "as-is" for production or easily customized.

Proposed Architecture

OmniCompute Blueprint Layers

Based on the OmniCompute architecture, this blueprint divides the collaborative inference system into the following core layers.

Architecture Layers

Core System Components

Layer 1

Application & API Layer

Agents or Applications based on Device-Edge-Cloud Collaborative AI Inference. Provides unified REST/gRPC endpoints, allowing higher-level applications to interact with the distributed edge-cloud infrastructure as if calling a single, unified model.

Layer 2

Collaborative Control Plane

The routing and security brain of the blueprint, consisting of Privacy Protection (Policy Check, PII Audit, Data Desensitization), Intelligent Routing (Task Complexity Analysis, Resource Awareness, Route Selection), and Adaptation (Resource Monitoring, Cost Analysis, Load Balancing).

Layer 3

Execution & Inference Data Plane

Inference Gateway (e.g., LiteLLM Proxy Server) acts as the critical bridge, standardizing protocols across all distributed models. Includes Local Inference Framework, Local XPU management, and Model Conversion Toolset for edge deployment.

Layer 4

Infrastructure Layer (KubeEdge)

Leveraging KubeEdge for seamless connectivity. Edge Node contains Local Controller and Worker, ensuring autonomous operation and local privacy. Cloud Node contains Global Manager and Worker managed by Kubernetes, handling global routing policies and model distribution.

Roadmap

Implementation Timeline

June - July 2026

Phase 1: Foundation

Draft final charter, select initial blueprint scope, and map out stakeholders. Define Cloud/Edge gateway API standards and KubeEdge CRD extensions.

August - September 2026

Phase 2: MVP Release

MVP reference implementation featuring static rule-based routing and basic privacy interceptors. Initial benchmarking on edge deployment targets and local XPU validation.

October - November 2026

Phase 3: Production Hardening

Hardened release: Dynamic intelligent routing based on task complexity, advanced observability, and telemetry. Partner pilot deployments and community adoption drives.
